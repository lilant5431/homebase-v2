## Diagnoses and corrections

The former composer used single-sample offscreen HDR targets: renderer canvas antialiasing did not cover that render path. The refinement uses **4× HDR MSAA** in the composer and planar reflection, derivative-aware facet junctions and stronger segmented orbital geometry. The core's old high radiance entered the tone mapper's flat white shoulder; the new narrower Gaussian spine uses a local emission shoulder and a luminance-preserving highlight shoulder, retaining brightness and window contrast. Exposure **1.12** and bloom **.18 / .35 / threshold 1.6** are unchanged. No geometry smoothing or cut change.

Refraction remains the same convex IOR 1.48 path with three bounded internal continuations. A fixed .65 probe LOD bounds excessive derivative-driven blur at discontinuous exit facets, trading some distant minification quality for more stable, clearer windows. Sign-preserving near-zero box-projection directions avoid division singularities. Default dispersion remains off; subtle/legacy comparisons remain explicit.

The crown-anchored beam uses **64** stable steps, a denser narrow axial column, a soft surrounding shell and less diffuse halo. Its energy remains powerful while the narrowed inner spine and controlled HDR highlights leave more facets visible. The beam and crystal retain their world transform connection; no bloom increase hides edges.

A **1536² half-float planar reflection** replaces the purple platform with a dark reflective receiver, platinum lips and ceramic outer rim. It reflects the actual current crystal/rails/beam, not a static image. The receiver is excluded from six-face probe capture to avoid feedback and recursive reflection rendering. The custom receiver shader keeps reflection color linear until the final OutputPass. The receiver target/material and geometry follow existing disposal/retry ownership. Six segmented platinum rails with recessed luminous channels and ceramic collars replace thin decorative filaments on each orbit. These are presentation structures, with no study-plan orb functionality.

## Causal interaction

A presentation-only event circuit compares navigation, beacon state, meaningful accumulated energy/focus changes and preview emphasis. It holds at most **eight** finite **five-second** wavefronts; idle time and camera inspection cannot generate events. A single bounded flash envelope affects the core, beam, source light and haze. The same spatial wavefront reaches the floor/receiver, ring channels and nearby particles at a common propagation speed. Large control adjustments visibly launch waves rather than merely changing a loop's amplitude. Reduced-motion/reference transitions clear queued waves on both entry and exit, preventing delayed playback.

All visible application branding/page titles/audition labels now say **Lumimark** ([planner capture](lumimark-planner.jpg)). Repository paths, storage keys, schema, backup names/encoding and academic/inference behavior remain unchanged. No migration, Canvas work, dependencies, production deployment or V1 changes.

## Measurements and tradeoffs

[Earlier production run](performance-f-production.txt), [final shader reload](performance-final-startup.txt), [after interactions](performance-after-events.txt), [warm recovery](performance-retry.txt), [development reading](performance-f-dev.txt). These are sampled desktop measurements, not universal performance guarantees or cold-network tests.

- Startup to first submission: **2098 ms** on the final fresh shader reload, **182 ms** on the preceding cached-program build; warm retries **111–119 ms**. Initial worst interval **1008.7 ms** accompanied shader initialization; later recovery-session worst **44.6 ms**. The long initial compile stall is a material remaining cost.
- Steady submitted rate about **164–166 FPS**, p95 interval **6.2–6.5 ms**. CPU submission samples **2.2–2.7 ms**, live GPU timer samples **3.0–4.4 ms**. Submitted rate is not display scanout, and samples are not GPU percentiles.
- Approximately **494–522 draw calls / 356–362k triangles** including all passes, versus roughly 290–310 / 190k in E. Planar reflection adds another scene submission; the 1024² six-face probe, MSAA resolves and shader ray/volume tracing remain major costs. No automatic fidelity reduction.
- Observed live counters **36 geometries / 18 textures / 33 programs**. Estimated HDR color attachments **287.3 MiB** versus E's 99.6 MiB: includes two multisampled main color targets, postprocessing, probe mip chain and multisampled reflector. Excludes depth, environment maps, driver allocations and total VRAM. Reflection attachment storage stays allocated in reference mode.
- Renderer chunk **595.47 kB / 152.69 kB gzip**. Existing lazy AI chunks still produce the build size warning; this task does not load them.

**Limitations:** 4× multisampled RGBA16F must be supported; unsupported capability/allocation reports a renderer failure while semantic workflows remain usable. No silent low-quality substitute. Tested only this Chromium/desktop GPU. Single-probe near-field parallax, critical-angle discontinuities, fixed LOD minification and thin reflected silhouettes can still shimmer; no TAA/path tracing. Highlight compression is art-directed and brightest tips/high-power previews can still approach white. Planar reflections are sharp rather than rough-convolved. Volume depth testing remains conservative, with no scene-depth-aware scattering or physical global illumination. Event waves coordinate illumination/emission, not a fluid or caustic simulation. The milestone improves clarity visibly, without claiming artifact-free offline-render quality.

Reference implementation inspected: installed Three.js r186 `EffectComposer`, `Reflector`, `WebGLTextures`, `ShaderMaterial` and multisample framebuffer behavior. Existing PRs remain open. No merge or deployment.
